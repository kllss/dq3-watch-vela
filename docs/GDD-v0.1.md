# 《勇者斗恶龙 III》Vela 手表版 · 游戏设计文档 v0.1

- 目标设备：REDMI Watch 6 普通版（432×514，矩形，触屏，旋转表冠，无可用返回键）
- 目标平台：Xiaomi Vela JS 应用（RPK）
- 原作基准：SFC《ドラゴンクエストIII そして伝説へ…》（1996，日本版）；具体 ROM 修订版与校验值 `[待核对]`
- 文档性质：**设计文档，不是实现，也不是对原作数据的声明**
- 前置文档：`docs/M0-仓库审计报告.md`
- 日期：2026-10-25

---

## 摘要（先看这 10 条）

1. **视野 11×9 格，36px/格**；地图以"点相邻格"为主，滑动为辅；表冠只用于菜单。
2. **两个页面：标题页（栈底）+ 游戏页**。游戏内部用模式状态机，不用路由承载流程，不拆 `.ux` 自定义组件。
   - 标题页当栈底是**必需的**：右滑返回无法关闭，单页 = 栈底 = 一滑就退出应用（已实测）；
   - 有标题页垫底后，游戏中右滑只是"回到标题"，不是"应用闪退"。
3. **战斗 5 指令**（攻击/咒文/防御/道具/逃走），消息自动前进，杂兵 20–40 秒。
4. **敌人不显示精确 HP**，只显示三档状态文字；血条默认关。
5. **数据表驱动**：职业、成长、怪物、物品、咒文、地图、事件全部 JSON；公式不写死。
6. **公式是候选实现**，M2 用样本校准；校准前不声称"忠实还原原作公式"。
7. **存档 = 自动槽 + 3 手动槽**，A/B 双写 + CRC + 版本迁移；教堂/国王手动存档。
8. **忠实度目标 F1–F3**（机制/数据/内容），不做 F4（原版美术/音乐/文本）。
9. **M5 拆成 a/b**：先做 30–60 分钟垂直切片，再铺完整内容。
10. **不引入原作资产**；公开版用原创中文文本与原创图形，个人自用可导入自备文本包。

## 1. 设计目标

### 1.1 一句话

**把 DQ3 的"探索—战斗—成长—推进剧情"完整地装进一块 432×514 的手表，用触屏和表冠替代手柄，用 3 分钟一次的快节奏会话替代 40 小时连续游玩。**

### 1.2 三条支柱

| 支柱 | 玩家感受 | 设计手段 |
|---|---|---|
| 再走一格 | "前面好像有东西，再看一眼" | 11×9 视野、步进式移动、低摩擦点击、可见的目标提示 |
| 再升一级 | "就差一点经验" | 20–40 秒杂兵战、升级页即时反馈、成长数值可见 |
| 再看一段 | "这句话之后发生了什么" | 3 行分页对话、选择按钮、冒险笔记记录最近线索 |

### 1.3 三条反支柱

- 不做"需要双手精密操作"的动作玩法。
- 不做"必须连续玩 30 分钟"的强制段落；任何时刻可以停下，自动存档。
- 不做"靠刷"填时长； encounters 和成长按原作节奏，不做额外数值墙。

### 1.4 忠实度的四个层级

这是本项目最重要的边界定义：

| 层级 | 内容 | 本作目标 |
|---|---|---|
| F1 机制 | 职业、咒文、道具、装备、战斗规则、状态、成长、转职、昼夜 | **必须一致** |
| F2 数据 | 地图拓扑、碰撞、遭遇表、怪物属性、价格、成长表 | **必须一致（可核对）** |
| F3 内容 | NPC、事件、剧情顺序、关键道具、结局 | **必须一致（可核对）** |
| F4 表现 | 原版点阵图、音乐、字体、文本措辞、动画 | **不做**；只用原创/授权资产 |

**结论：目标是 F1–F3，不是"像素级复刻"。** 任何"看起来像原作"的美术/音乐都不在范围内；任何"机制不一样"的地方都必须记录在差异清单里。

### 1.5 与原作的差异清单（必须随版本更新）

| # | 差异 | 原因 | 是否可接受 |
|---|---|---|---|
| D1 | 视口从原作的宽屏改为 11×9 格 | 432×514 屏幕 | 是 |
| D2 | 触屏点击相邻格 + 滑动替代方向键 | 无实体十字键 | 是 |
| D3 | 表冠只用于菜单/列表，不用于地图 | `swipe` 与 `scroll` 冲突；方向符号未验证 | 是 |
| D4 | 文本 3 行分页、无打字机效果 | 小屏可读性 + 减少重渲染 | 是 |
| D5 | 战斗消息自动前进 + 点击跳过 | 避免一回合点 20 次 | 是 |
| D6 | 自动存档 + 快速继续 | 应用可能被系统回收 | 是 |
| D7 | 指令记忆/自动普攻（可选） | 手表操作成本 | 是，默认关 |
| D8 | 装备对比、冒险笔记、目标提示 | 小屏记忆负担 | 是 |
| D9 | 无原版音乐/音效 | 版权 + 未验证音频能力 | 是 |
| D10 | 无怪物动画，仅静态图标/文字反馈 | 无 canvas | 是 |
| D11 | 中文文本（原作日文） | 目标用户 | 是，需原创/授权 |
| D12 | 可能裁减可选玩法（怪物竞技场、双六、小徽章、通关后洞窟、怪物徽章等） | 工作量与数据依赖 | 待定 `[待核对]` |

## 2. 平台约束如何变成设计规则

| 约束 | 来源 | 设计规则 |
|---|---|---|
| 432×514，矩形 | 实测 | 所有布局以 432 宽为基准；底部 56px、左右 16px 为安全区 |
| 无返回键 | 3 轮实测未触发 | 每个非地图界面左上角固定 `‹ 返回`；地图左上角固定 `暂停` |
| 表冠只有 scroll 位移 | 实测 51 次、−160px | 只在菜单用；累加阈值；切视图重置基线 |
| 表冠方向未验证 | 四轮 dy 全为负 | `CROWN_SIGN` 常量；M1 实测后再定 |
| 右滑**确认会退出**（栈底），无法关闭 | 实测 2026-10-25 | 标题页当栈底 + 地图不用横滑；见 [实测记录 01](https://github.com/kllss/redmi-watch-6-vela-input/blob/main/docs/device-results-01-back-swipe.md)（平台研究仓库） |
| 无 canvas | 官方组件清单 | 地图/战斗全部用 `div`/`text`；步进刷新，不做 60fps |
| 官方不建议手表用自定义组件 | 官方文档 | 页面只两个（标题 + 游戏）；游戏内部纯 JS 状态机，不拆 `.ux` 组件 |
| 存储只能存字符串 | 官方文档 | 存档 JSON + CRC；A/B 双槽 |
| 应用可能被回收 | 平台常识 | 自动存档 + 启动即恢复；状态全部可序列化 |
| 无 logcat | 实测环境 | 屏幕日志 + CODE 汇总 + 崩溃落盘 |
| 加速度计 11Hz | 实测 | 不做体感移动；最多做"倾斜辅助"（默认关，M4 再评估） |

### 2.1 一条必须遵守的"不假设"清单

- 不假设 `onBackPress` 会来。
- 不假设表冠有按下/双击/长按。
- 不假设 `swipe` 在有滚动容器时还能触发。
- 不假设 `storage` 能存对象或大字符串。
- 不假设 `router` 返回后页面状态还在。
- 不假设 `device.getInfo` 的 APILevel 是真的。
- 不假设自定义组件在手表上内存可接受。
- 不假设 60fps；一切按"步进"设计。

## 3. 核心体验

### 3.1 核心循环

```
        ┌──────────────┐
        │  看线索/对话  │
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │  走进新区域   │ ←──── 目标提示/冒险笔记
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │  随机遭遇     │
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │  战斗 20–40s  │
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │ 经验/金币/掉落 │
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │ 回城/升级/存档 │
        └──────┬───────┘
               ↓
        ┌──────────────┐
        │ 解锁下一段剧情 │
        └──────────────┘
```

### 3.2 会话设计

| 项目 | 目标 |
|---|---|
| 单次会话 | 3–8 分钟 |
| 一次会话能完成 | 2–4 场杂兵战 + 1 段对话 + 1 次菜单操作 |
| 随时中断 | 任何界面都能直接退出；下次从最近自动存档继续 |
| 启动到可操作 | 目标 < 3 秒（M1 测） |
| 一局战斗 | 杂兵 20–40 秒；Boss 2–5 分钟 |
| 一次升级 | 正常推进下 10–20 分钟一级（前期更快） |

### 3.3 玩家在手表上的姿势

- 手表戴在左手，右手操作；
- 主要按钮放右下，返回放左上；
- 表冠在右侧，右手拇指/食指自然可转；
- 主操作（确认/取消/暂停/购买/存档）≥ 64×64；
- 战斗指令与列表行 ≥ 52 高、≥ 72 宽；地图格 36×36，点击按相邻格判定；
- 不做需要"按住不放 + 同时转表冠"的组合操作。

### 3.4 前 10 分钟：第一次上手必须发生什么

这是一段"体验脚本"，不是剧情文本；目的是让玩家在不看说明书的情况下学会全部操作。

| 时间 | 画面 | 玩家学到什么 | 设计手段 |
|---|---|---|---|
| 0:00 | 标题 | 继续/新游戏 | 有存档时"继续"默认高亮 |
| 0:03 | 开场 1 页 | 点一下翻页 | 右下 `▼` + 一次脉冲 |
| 0:20 | 地图 | 点相邻格移动 | 一次性浮层"点身边的格子走一步"，点任意处消失 |
| 0:40 | NPC 对话 | 点对话框继续 | 对话框整体是点击区，不给小按钮 |
| 1:30 | 第一场遭遇 | 点"攻击"→点敌人 | 指令区高亮"攻击"；敌人行整体可点 |
| 2:30 | 升级页 | 成长是可见的 | 属性前后对比 + 新咒文提示 |
| 3:00 | 菜单 | 菜单在哪、怎么退 | 第一次打开菜单时，"返回"按钮脉冲一次 |
| 5:00 | 教堂/自动存档 | 存档是安全的 | 存档成功一行"已自动保存" |
| 8:00 | 第一个洞窟入口 | 探索有纵深 | 入口前一个 NPC 给一句方向提示 |
| 10:00 | 第一个小 Boss 或剧情钩子 | 继续玩的理由 | 战斗后给一个明确的"下一目标" |

规则：

- 同一时间只显示一条提示；
- 玩家已经做过该动作，就不再显示；
- 提示不阻塞输入，点任意处立即消失；
- 所有提示只出现一次，存在 `flags` 里；
- 任何提示都不能遮住"返回/暂停"。

## 4. 操作设计

### 4.1 统一动作集

```js
UP / DOWN / LEFT / RIGHT      // 地图移动、列表上下
CONFIRM / CANCEL              // 确认/取消
MENU                          // 打开主菜单
TALK / SEARCH                 // 语境动作
PAGE_NEXT / PAGE_PREV         // 对话/说明分页
PAUSE                         // 暂停面板
DEBUG                         // 调试（仅开发版）
```

### 4.2 原始输入 → 动作

| 原始输入 | 动作 | 使用场景 | 备注 |
|---|---|---|---|
| `click` 地图相邻格 | 方向 | 地图 | 主路径；精确、无手势冲突 |
| `touchstart`+`touchend` 位移 > 24px | 方向 | 地图 | 副路径；主轴判定；右滑需 M1 验证 |
| `click` 对话区 | PAGE_NEXT | 对话 | **只绑 click**，不同时绑 touchend |
| `click` 菜单行 | CONFIRM | 菜单 | 行本身是点击目标 |
| `click` 大按钮 | 语义动作 | 全局 | 按钮尺寸 ≥ 64 |
| 表冠 `onscroll` | UP/DOWN | 菜单/列表 | 累加 24px 一步；120ms 冷却 |
| `onBackPress` | CANCEL/PAUSE | 全局 | 仅兜底；不作为唯一入口 |
| 加速度计 | 无 | — | 默认不绑定；M4 再评估倾斜辅助 |

### 4.3 手势规则

> 地图移动与右滑系统返回的完整方案见 `docs/地图移动与手势规避方案.md`；交互演示见 `design/map-movement-demo.html`。
> 核心结论：地图以"点相邻格"为主；横向默认不滑；中心区域只做竖向拖动；左边缘 72px 不参与移动。

1. **点击优先**：地图上点相邻格比滑动更准，默认主路径。
2. **滑动阈值**：`max(|dx|,|dy|) >= 24`，且主轴比 `>= 1.5`；否则视为点击。
3. **一次滑动只走一步**：不做惯性连续移动；连续走需要连续滑或连点。
4. **右边缘禁用横滑**：M1 验证前，地图横滑从屏幕左侧 80% 区域起手；右边缘 60px 不响应横滑。
5. **对话只认 click**：避免 `click` + `touchend` 双触发。
6. **菜单行只认 click**：不做"滑动选中 + 点击确认"的复合手势。
7. **输入锁**：任何模式切换后 200ms 内丢弃所有输入；异步操作（存档/切图）期间 `busy=true`。
8. **去抖**：同一动作 120ms 内只接受一次；表冠单独用 120ms 冷却。

### 4.4 表冠策略 `[决定]`

- **地图**：默认不用表冠。M1 用右侧 80px 窄条测试；只有确认窄条能被驱动，才作为"上下移动"的可选辅助（默认关）。
- **菜单/列表**：使用表冠。列表本身就是 `scroll`，选中项由滚动位置决定：

```js
onScroll(e) {
  if (now < suppressUntil) return
  const idx = clamp(Math.round(e.scrollY / ROW_H), 0, rows.length - 1)
  if (idx !== sel) { sel = idx; haptics.short() }
}
```

- **进入菜单**：`scrollTo(sel * ROW_H, instant)`，`suppressUntil = now + 250`。
- **离开菜单**：`scrollY = 0; suppressUntil = now + 250`。
- **方向反转**：只改 `CROWN_SIGN = ±1`，不改逻辑。
- **不可用兜底**：所有菜单都能纯点击完成；表冠只是加速器。

### 4.5 软件返回/暂停 `[决定]`

| 界面 | 左上角 | 右上角 |
|---|---|---|
| 地图 | `暂停` | `菜单` |
| 对话 | `‹ 返回`（仅非强制对话） | — |
| 菜单 | `‹ 返回` | — |
| 战斗（选指令） | `‹ 撤退`（仅非 Boss） | `自动`（可选） |
| 商店/旅馆/教堂 | `‹ 返回` | — |
| 存档 | `‹ 返回` | — |

暂停面板：`继续 / 存档 / 读档 / 冒险笔记 / 设置 / 回标题`。回标题需长按 600ms + 二次确认。

### 4.6 模式状态机与动作矩阵

```
TITLE ──继续/新游戏──> FIELD
FIELD ⇄ DIALOG
FIELD ──菜单──> MENU ──> STATUS / EQUIP / ITEM / SPELL / PARTY / SAVE
FIELD ──NPC/门──> SHOP / INN / CHURCH / EVENT
FIELD ──遇敌──> BATTLE_COMMAND → BATTLE_TARGET → BATTLE_RESOLVE → RESULT → FIELD
FIELD/MENU ──暂停──> PAUSED ──回标题──> TITLE
BATTLE ──全灭──> GAME_OVER ──> CHURCH / TITLE
```

动作矩阵（`—` = 丢弃）：

| 模式 | UP/DOWN | LEFT/RIGHT | CONFIRM | CANCEL | MENU | PAGE_NEXT |
|---|---|---|---|---|---|---|
| FIELD | 移动 | 移动 | 交互 | 暂停 | 打开菜单 | — |
| DIALOG | — | — | 翻页 | 关闭（非强制） | — | 翻页 |
| MENU | 选择 | — | 进入 | 返回 | 关闭 | — |
| STATUS/EQUIP/ITEM | 选择 | — | 进入/装备/使用 | 返回 | — | — |
| BATTLE_COMMAND | 选择 | 选择 | 进入目标/确认 | 返回 | — | — |
| BATTLE_TARGET | 选择目标 | — | 确认 | 返回 | — | — |
| BATTLE_RESOLVE | — | — | 跳过消息 | — | — | — |
| SHOP/INN/CHURCH | 选择 | — | 确认 | 返回 | — | — |
| SAVE | 选择槽 | — | 保存/读取 | 返回 | — | — |
| PAUSED | 选择 | — | 确认 | 继续 | — | — |
| GAME_OVER | 选择 | — | 确认 | — | — | — |

转换规则：

1. 所有模式切换走 `Game.enter(mode)`，统一设置 `inputLockUntil = now + 200`；
2. `Game.enter` 清空瞬时状态（当前选中项、滚动基线、消息队列）；
3. `DIALOG` 出现选项时，`PAGE_NEXT` 被禁用，必须走 `CONFIRM`；
4. `BATTLE` 不能直接打开 `MENU`/`PAUSED`（避免战斗中存档）；

### 6.5 成长 `[原作]`（已从 ROM 提取）

不做"公式生成"，做**职业表驱动**。ROM 实测（`$C4179E`，9 × `0x173`）的结构是：

- 初始值（男/女）；
- 若干 `{ 等级, 增量 }`：在指定等级**一次性加一笔**，不是每级线性；
- 98 级经验表（升到 2..99 级所需 EXP）；
- 咒文学习表（`{等级, 咒文 ID}`）。

Warrior 力量的真实数据：

```json
{
  "className": "Warrior",
  "statCap": 255,
  "growth": {
    "strength": {
      "maleInitial": 9,
      "femaleInitial": 8,
      "bonuses": [
        { "level": 8,   "amount": 48 },
        { "level": 32,  "amount": 64 },
        { "level": 47,  "amount": 48 },
        { "level": 100, "amount": 24 }
      ],
      "maleAt99": 193,
      "femaleAt99": 192
    }
  }
}
```

说明：

- 满级 9 + 48 + 64 + 48 + 24 = 193，符合战士的力量量级；
- 属性上限 255；Fighter 力量、Jester 运气、Hero 耐力会超过 255，**引擎必须封顶**；
- 原作说明"每级成长是伪随机、范围随职业"，这部分浮动区间还没从 ROM 里确定，M3 用实机样本校准；
- 不再使用"每级 min/max 表"的假设；那是上一版的设计占位，不是 ROM 结构。

数据量：9 职业 ×（98 EXP + 约 60 个成长字节 + 咒文表）≈ 几 KB，完全可接受。

### 6.6 属性与派生值 `[候选]`

以下全部是**本作候选实现**，不是原作公式；M2 用样本校准。

```
攻击力 = 力量 + 武器攻击
防御力 = 防御 / 2 + 防具 + 盾 + 头盔 + 饰品
命中率 = clamp(0.95 - 回避/64 + (攻方敏捷 - 守方敏捷) / 256, 0.30, 0.98)
暴击率 = clamp(1/64 + 攻方运气 / 2048, 1/64, 1/8)
普通伤害 = max(1, round((攻击力 - 防御力 / 2) * rand(0.85, 1.15)))
咒文伤害 = max(1, round((基础值 + 智力 / 4) * 抗性 * rand(0.90, 1.10)))
回复量 = round((基础值 + 智力 / 4) * rand(0.90, 1.10))
行动顺序 = 按 (敏捷 + rand(0, 敏捷/8)) 降序，同速随机
逃跑率 = clamp(0.35 + (我方平均敏捷 - 敌方平均敏捷) / 128, 0.10, 0.90)；Boss = 0
```

注：回避值按 `x/64` 表示（公开资料里常见 0/64、1/64、1/32 等）；ROM 怪物表里的 `mikawashi` 是 3 位字段，**是否等于回避尚未确认**，M2 校准。

校准方法（M2）：

1. 在模拟器/原作里固定一组属性，记录 20 次普通攻击伤害；
2. 用 `tools/calibrate.mjs` 拟合 `攻/防/系数/方差`；
3. 把拟合结果写回 `data/formulas.json`；
4. 单元测试锁定"给定种子 → 给定伤害序列"，防止回退。

**没有校准前，不得在文档/发布说明里写"忠实还原原作公式"。**

### 6.7 战斗流程 `[决定]`

```

**切片流程（体验层，不是原作剧情文本）**：

```

- 全程不需要读文档；
- 不出现"卡住但不知道去哪"；
- 所有界面至少被打开过一次；
- 所有系统至少被使用过一次；
- 30–60 分钟内可完成；

### 8.4 文本与本地化

#### 文本 key 规则

- 代码和脚本里**不出现中文/日文显示文本**，只出现 key；
- key 命名：`ui.*`、`dialog.*`、`monster.*`、`item.*`、`spell.*`、`class.*`、`system.*`；

- 选项按钮也是 key（如 `txt.common.yes`），不是硬编码"是/否"；
- 改名要同步迁移表，不能悄悄改 key。

#### 实体名称

```json
{ "id": "slime", "nameKey": "monster.slime", "name": "史莱姆" }
```

- `name` 是默认显示（中文），`nameKey` 存在时以文本表为准；
- 这样数据表仍然可读，同时保留换语言的能力；
- 构建时校验：`nameKey` 必须存在于当前语言表。

- 每页最多 3 行；
- 断行优先级：`。！？；` > `，、` > 空格 > 强制断；
- 行首禁止：`。，、；：！？）」』`；
- 行尾禁止：`（「『`；
- 不用打字机效果；一次渲染整页。

#### 文本量预算

| 类型 | 估算 | 说明 |
|---|---|---|
| 主线对话 | 300–500 段 | 每段 1–4 页 |
| NPC 闲聊 | 300–500 条 | 每条约 1–2 页 |

### 8.5 数据来源与生成流程

```
用户自备 ROM（不提交、不打包）
        ↓  tools/extract/*.mjs（离线 Node）
   data/raw/*.json（本地，gitignored）
        ↓  tools/validate.mjs
   data/release/*.json（进 RPK 的派生数据）
        ↓  tools/manifest.mjs
   data.manifest.json（ROM 校验 + 表校验 + 计数）
```

规则：

1. `data.manifest.json` 必须记录：源 ROM 的 SHA-1/CRC32、地区/修订版、提取器版本、每张表的 SHA-1 与行数；
2. 同一 ROM + 同一提取器 → 同一份数据哈希，可复现；
3. `data/raw/` 与任何 ROM/原版素材都不进 git；
4. 无法提取的表（例如公式、AI 权重）必须标 `unverified`，并写清来源/推断依据；
5. 构建时把 `data.manifest.json` 的版本写进游戏"关于"页，便于对应；
6. 如果某张表只有部分数据，宁可缺项并报错，不要用编造值补全。

## 9. 存档设计

### 9.1 槽位

| 槽 | 写入时机 | 用途 |
|---|---|---|
| 自动 | 战斗结束/地图切换/商店/升级/**回到标题页** | 防系统回收、防右滑误退 |
| 手动 1–3 | 教堂/国王 | 玩家可控回退 |

### 9.1.1 为什么"回到标题页"这个时机特别可靠

右滑返回关不掉（`followHand` 实测无效），所以游戏上垫一层标题页：右滑只是把游戏页 pop 掉，回到标题。

关键在于**进程还在**：

| 场景 | 进程状态 | 异步写入有没有时间落地 |
|---|---|---|
| 玩家右滑退出应用（栈底） | 结束 | 没有，写一半就没了 |
| 游戏中右滑 → 回到标题页 | 存活 | **有**，`storage.set` 几毫秒就完成 |

所以在 `Title.onShow` 里写一次存档，比在 `Game.onDestroy` 里写更稳：前者是"页面已经切完、进程确定还活着"，后者是"页面正在销毁，随时可能被一起收走"。

配套规则：

- `store.inGame` 标记玩家是否在游戏中，只有"从游戏回来"才触发这次存档，启动时进标题不写；
- 写入完成后标题页显示一行"已自动保存 · Lv12 阿利亚罕 · 15:03"，让玩家看得见；
- 写失败要显式提示，不要静默——这行提示本身就是"可以安全退出"的凭证；
- 不依赖"玩家不会连滑两次"：即使第二次右滑立刻退出，上一步的写入已经完成。

### 9.2 写入

```
encode: {v, crc, body}
slotA / slotB 交替写；generation 递增
load: 两个槽都 decode，取 generation 最大且 crc 正确的
```

- 写入前先 `storage.get` 读旧值，成功后写新槽；
- 如果 `storage.set` 失败，保留旧槽，界面提示"存档失败，请重试"；
- 不调用 `storage.clear`（会清掉所有键）；
- 空字符串会删除键，所以存档字符串一定有非空前缀 `{"v":1,...}`。

### 9.3 版本迁移

- `v` 字段；
- 迁移函数表：`1→2`、`2→3`；
- 未知高版本 → 拒绝加载，提示"存档来自更新版本"；
- 低版本 → 逐级迁移；
- 迁移失败 → 保留原数据，不覆盖。

### 9.4 损坏恢复

| 情况 | 行为 |
|---|---|
| JSON 解析失败 | 尝试另一个槽 |
| CRC 错 | 尝试另一个槽 |
| 版本过高 | 拒绝，提示 |
| 两个槽都坏 | 提供"新游戏"；保留坏数据到 `crash_save` 键，便于排查 |
| 地图 id 不存在 | 回到最近教堂，提示"存档位置无效" |

### 10.2 难度选项 `[决定]`

| 选项 | 默认 | 效果 |
|---|---|---|
| 减少遭遇 | 关 | 遇敌概率 ×0.5 |
| 战斗加速 | 开 | 消息 700ms → 350ms |
| 指令记忆 | 开 | 长按攻击重复上次指令 |

| 高对比度 | 关 | 提高前景/背景对比 |
| 字体放大 | 100% | 115% / 130%，需要重新排版 |

难度选项不改变数据，只改变呈现/频率；开启后不影响"忠实度"声明（因为默认关）。

### 10.3 节奏规则

- 每 10–15 分钟必须有一次"有意义的选择"（升级、装备、剧情选择、新区域）；
- 每 3 分钟至少一次自动存档；
- 连续 3 场杂兵战后，第 4 场概率下降（避免疲劳）；
- Boss 前必须有回复点/存档点；
- 迷宫长度控制在 10–15 分钟以内（手表会话）。
