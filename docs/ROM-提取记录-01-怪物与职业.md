## 1. 怪物表

### 1.1 位置与结构

| 项目 | 值 |
|---|---|
| CPU 地址 | `$C20000` |
| 文件偏移 | `0x020000`（HiROM：`$C2:0000` → `0x020000`） |
| 记录长度 | `0x25`（37）字节 |
| 文档条目数 | `0xA1`（161） |
| 实际有效 | `0..159`（160 条）；第 161 条是填充/越界 |
| 名称表 | `$FECFB7` → `0x3ECFB7`，958 条，`0xAC` 结尾 |
| 掉落概率表 | `$C2AA34` → `0x02AA34`，8 个 u16le 阈值，分母 1024 |

字段（按 Datacrystal）：

| 偏移 | 字段 |
|---|---|
| `$00-$01` | 名称字符串索引 |
| `$02` | 等级（低 6 位）、龙/僵尸标志 |
| `$03-$04` | 经验 |
| `$05-$06` | 金币（10 位） |
| `$06-$07` | 攻击（10 位） |
| `$07-$08` | 防御（10 位） |
| `$08-$09` | 调色板 |
| `$0a` | 敏捷 |
| `$0b` | MP |
| `$0c` | 掉落物品 ID |
| `$0d` | 精灵 ID |
| `$0e-$16` | 8 个 9 位指令 |
| `$17` | 指令约束位 |
| `$18-$1c` | 动画 / 指令选择 / 策略 |
| `$1d` | 见切、掉落概率索引、多动 |
| `$1e-$21` | 14 类抗性（每类 2 位） |
| `$22-$23` | HP |
| `$24` | 金属标志 |

### 1.3 一个重要偏差：160 条 ≠ 155 个官方 ID

公开列表的怪物 ID 到 `$9B`（155）为止，之后 `$9C-$A0` 是空。ROM 表里却有 160 条有效记录，原因是插入了 Boss/变体：

| 记录 | 名称 | 说明 |
|---|---|---|
| 135 | ゾーマ | 第一阶段 |
| 136 | ゾーマ | 第二阶段 |
| 138 | カンダタ | 变体 A |
| 139 | カンダタ | 变体 B |
| 140 | カンダタこぶん | 变体 A |
| 159 | カンダタこぶん | 变体 B |
| 141 | けいけんち | 内部伪怪物（经验值） |
| 142 | おかね | 内部伪怪物（金币） |
| 143–149 | せんたく… | 内部选择项 |

因此：

- **前 134 条**的记录索引 = 官方 ID；
- **135 之后**不能直接把记录索引当官方 ID；
- 做遭遇表/图鉴时，要单独维护 `recordId ↔ officialId` 映射；
- Boss 的两个阶段都要保留，不能只留一个。

### 1.4 掉落概率表

`0x02AA34` 的 8 个 u16le：

| 索引 | 阈值 | 近似概率 |
|---|---|---|
| 0 | 0 | 0 |
| 1 | 7 | 1/146 |
| 2 | 15 | 1/68 |
| 3 | 31 | 1/33 |

### 1.5 抗性

每条记录有 14 个 2 位值，顺序按公开资料：

```
炎 / 冰 / 风 / 雷 / 即死 / 自爆 / 光 / 幻惑 /
睡眠 / MP吸收 / 封魔 / 混乱 / 防御下降 / 敏捷下降
```

原始值 0–3；`0/1/2/3` 对应 `×/△/○/◎` 的映射还没校准，**不要先写死倍率**。

**这修正了 GDD 里的两个错误：**

1. 职业是 **9 个**，不是 8 个；SFC 版有 **盗贼（とうぞく）**。
2. 商人不是"无咒文"，而是 **2 个咒文**（Lv12 / Lv17）；游玩人有 **1 个**（Lv13）。

### 2.3 咒文学习表

每条 2 字节：`(等级, 咒文 ID)`，按等级升序。例：

```json
Dealer:  [{ "level": 12, "spellId": 71 }, { "level": 17, "spellId": 72 }]
Jester:  [{ "level": 13, "spellId": 70 }]
Thief:   [{ "level": 8,  "spellId": 65 }, { "level": 10, "spellId": 66 },
          { "level": 13, "spellId": 68 }, { "level": 17, "spellId": 67 },
          { "level": 20, "spellId": 69 }]
```

咒文 ID → 名称还要等咒文表；这里先保留数字。

### 2.4 成长模型

每个属性存的是：

```
初始值（男/女）
+ 若干条 { 等级, 增量 }
```

例：Warrior 力量：

```
初始 9（男）/ 8（女）
Lv8  +48
Lv32 +64
Lv47 +48
Lv100 +24
→ 满级 9 + 48 + 64 + 48 + 24 = 193
```

这比"每级固定加值"更符合原作：成长是**在特定等级一次性加一笔**，不是线性。最后一条 `{level:1, amount:0}` 是终止符，已过滤。

验证：

| 职业 | 属性 | 满级总和 | 备注 |
|---|---|---|---|
| Warrior | 力量 | 193 | 合理 |
| Warrior | 耐力/HP | 245 | 合理 |
| Hero | 力量 | 202 | 合理 |
| Hero | 耐力/HP | 312 | 超过 255，游戏内封顶 |
| Fighter | 力量 | 306 | 超过 255，游戏内封顶 |
| Jester | 运气 | 470 | 超过 255，游戏内封顶 |

**结论：模型可用，但"超过 255 封顶"必须在引擎里实现。**

## 3. 现在能确认什么、不能确认什么

### 已确认（ROM + 公开资料交叉）

- ROM 版本、哈希、HiROM 映射；
- 怪物表地址/长度/字段/名称；
- 160 条记录 = 1 条空记录 + 155 个官方怪物 + 若干 Boss/伪怪物变体（见 1.3）；
- 职业表地址/长度/9 个职业；
- 98 级经验表；
- 咒文学习表结构；
- 成长是"等级触发的一次性增量"，不是线性。

### 仍未确认（需要 RAM / 实机）

- 抗性 0–3 与 `×/△/○/◎` 的对应；
- 掉落概率的 `<` / `<=` 判定；
- 指令 ID 的含义（攻击/咒文/逃跑/蓄力等）；
- `$1d` 的"见切"、多动、集中攻击等字段语义；
- 怪物 AI 的权重/策略表；
- 伤害/命中/暴击公式；
- 道具表、咒文表、商店表、遭遇表、地图、事件——**尚未提取**；
- Healslime MP 255 是否真的是"无限 MP"（大概率是，但未验证）。
